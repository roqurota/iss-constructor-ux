# ISS CONSTRUCTOR V2\n\nRuntime State Model\n\nState machines, lifecycle, cancellation, concurrency and deterministic runtime semantics\n\nEngineering baseline derived from Architecture A-012–A-036\n\n### 1. Purpose\n\nThis document defines what the Player is allowed to be doing at runtime, which subsystem owns each piece of transient state, and how events transform that state. It is normative for Player and Full Runtime Preview.\n\n- Runtime state is transient and is not written back into the Working Project.\n\n- Preview and Player execute the same state semantics.\n\n- Events are accepted in arrival order; long-running effects do not globally block later events.\n\n- Later state-setting operations normally win on the same target; additive/side-effect actions retain their own semantics.\n\n- Lifecycle ownership determines cancellation: leaving an owner cancels its owned pending work.\n\n- Reset/restart returns affected scope to a defined clean state rather than reconstructing an exact crash-time snapshot.\n\n### 2. Variables\n\n- Variable mutations are ordered through normal event processing.\n\n- Set X=5 then Set X=10 results in 10.\n\n- Add +1 repeated five accepted times adds five.\n\n- Reset Screen resets Screen variables to defaults; shared variables change only if reset policy/action explicitly targets them.\n\n### 15. Background media on Page\n\n- Page background image/video/playlist is Page-owned media.\n\n- Background video/media may autoplay, loop and play sound with configurable volume/mute.\n\n- It starts/stops with Page lifecycle unless a future explicit persistence feature says otherwise.\n\n- Screen Media Player is independent and may temporarily cover the Page.\n\n- Therefore V1 Screenless Mode requires no special V2 state machine: an Idle Page with audible looping background plus externally triggered Screen Media Player reproduces the behavior.\n\n### 18. Same-PC multi-display coordination\n\n- Each logical Screen has its own ScreenRuntimeSession and renderer window where assigned.\n\n- RuntimeCoordinator routes cross-Screen actions by logical ScreenId.\n\n- Physical Display identity is never an action target.\n\n- Shared Player Variables are common to all Screen sessions on that Player.\n\n- Unavailable target Screen fails safely and is diagnosable; it does not stop unrelated Screens.\n\n### 21. Runtime generation tokens\n\nTo make stale asynchronous completion safe, runtime owners should use generation/session tokens.\n\npageGeneration = 42
start async work owned by Page generation 42
navigate away → generation becomes 43
old async callback returns with ownerGeneration 42
42 != 43 → ignore result\n\nEquivalent ownership tokens should be used for media preparation, renderer/session recreation and other async operations where late completion could otherwise resurrect obsolete state.\n\n### 25. Logging and trace requirements\n\n- Every runtime event may be correlated with ScreenId, PageId, trigger source and timestamp.\n\n- Action trace records action type, target, result and failure reason.\n\n- Media diagnostics expose state, content/item, preparation/readiness and playback position.\n\n- Network diagnostics expose IN/OUT, source/destination, payload, matched trigger and resulting actions.\n\n- Multi-PC diagnostics expose node connection, clock-sync state and distributed operation phase.\n\n- Visitor UI never displays raw technical trace data.\n\n### 26. Runtime invariants\n\nRT-INV-01  Exactly one active PageRuntime exists per normal ScreenRuntimeSession.\n\nRT-INV-02  Exactly one system Screen Media Player exists per Screen.\n\nRT-INV-03  Page Leave always invalidates Page-owned pending asynchronous work.\n\nRT-INV-04  Runtime state never mutates ProjectDocument.\n\nRT-INV-05  Physical Displays are not runtime behavior targets.\n\nRT-INV-06  Popups cannot outlive their owning Page.\n\nRT-INV-07  Screensaver visibility does not cause Page Leave/Enter.\n\nRT-INV-08  Page Timeline continues beneath Screensaver/Screen Media Player unless explicitly stopped.\n\nRT-INV-09  Reset Screen produces a clean initial Screen state.\n\nRT-INV-10  Stale async completion cannot resurrect obsolete Page/media state.\n\nRT-INV-11  One Screen failure must not intentionally terminate healthy Screens.\n\nRT-INV-12  Cross-PC synchronization is installation/runtime coordination, not a project Action flag.\n\nRT-INV-13  V1 Screenless behavior is represented by ordinary Page background media with audio, not a separate mode.\n\n### 27. Required runtime test families\n\n### 28. Deferred / intentionally unspecified\n\n- Persistent runtime state across Player restarts.\n\n- Automatic replay of missed cross-PC history.\n\n- Continuous playback drift correction after synchronized start.\n\n- General-purpose Repeat/Wait Until/Cancel Flow language beyond currently approved control steps.\n\n- Exact decoder-specific seek event edge policy beyond deterministic no-jitter-duplication requirement.\n\n- Per-widget internal state machines; each Widget Contract defines those separately.\n\n### 29.
