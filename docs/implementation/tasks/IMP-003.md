# IMP-003 — Project persistence, atomic save and migration

- **Wave:** 1
- **Dependencies:** IMP-002
- **Allowed scope:** packages/project-model persistence
- **Non-goal:** No UI beyond callable services.

## Requirements
- `ENG-PERSIST-001` — `.iss` contain authoring model and stable projectId plus independent formatVersion.
- `ENG-PERSIST-002` — formatVersion change only for persistent schema compatibility changes, not every app release.
- `ENG-PERSIST-003` — Migration run forward sequentially in memory before normal editing.
- `ENG-PERSIST-004` — Original project file remain untouched until explicit Save.
- `ENG-PERSIST-005` — First Save after migration create migration backup before replacing original.
- `ENG-PERSIST-006` — Unsupported newer format fail safely without destructive rewrite.
- `ENG-PERSIST-007` — Unsaved work recovery use a separate debounced recovery snapshot keyed by projectId.
- `ENG-PERSIST-008` — Recovery snapshot MUST NOT replace normal `.iss` save semantics.
- `ENG-PERSIST-009` — After abnormal restart, Constructor offer Recover/Discard when valid recovery exists.
- `ENG-PERSIST-010` — Normal close with dirty project support Save / Don't Save / Cancel; Don't Save removes stale recovery for that session.
- `ENG-PERSIST-011` — Copy/Duplicate/Import discover owned graph, allocate new IDs, rewrite internal references, preserve external dependencies and commit atomically as one Project Operation.
