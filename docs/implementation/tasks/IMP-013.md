# IMP-013 — Action registry and Behavior Flow engine

- **Wave:** 2
- **Dependencies:** IMP-002
- **Allowed scope:** packages/actions + runtime-engine
- **Non-goal:** Transport-independent.

## Requirements
- `ENG-ACT-015` — Trigger families include pointer/touch, keyboard, mouse, network, timeline, media event, variable changed, lifecycle, idle and widget triggers where supported.
- `ENG-ACT-016` — External/network events use the same Action Engine as local UI events.
- `ENG-ACT-001` — Represent project-visible behavior as ordered Behavior Flows containing Actions and Control Steps.
- `ENG-ACT-002` — Initial Control Steps include Delay and If/Condition.
- `ENG-ACT-003` — Action dispatch use an extensible registry/handler model rather than hard-coded UI branching.
- `ENG-ACT-004` — Action definitions contain action type, optional logical target and typed/validated parameters.
- `ENG-ACT-014` — One Trigger may start a Behavior Flow containing multiple Actions.
- `ENG-ACT-017` — Action handlers fail safely for unavailable/invalid targets and return diagnosable outcomes.
- `ENG-ACT-018` — Introduce a second parallel command system for Widgets, network or Player controls.
- `ENG-RT-001` — Route project-visible events through Trigger → Behavior Flow → Action Engine.
- `ENG-RT-002` — Process accepted events in observed arrival order without a global busy lock.
- `ENG-RT-003` — A Delay pauses only its owning Behavior Flow.
